# User Flows

이 문서는 사용자가 `익명 대화 -> 친구 요청 -> 친구 수락 -> 프로필 공개`로 넘어가는 핵심 흐름을 정리합니다.

## Flow 1. 익명 그룹채팅 진입

1. 사용자가 앱에 로그인한다.
2. 공개 그룹채팅을 탐색하거나 검색한다.
3. 채팅방에 참여한다.
4. 채팅방 안에서는 익명 식별자로 대화한다.

체크포인트:

- [x] 공개 그룹채팅 탐색 흐름이 있다.
- [x] 그룹채팅 참여 후 방 안 컨텍스트가 있다.
- [x] 방 안 익명 식별자 개념이 있다.
- [ ] 익명 상태를 더 분명히 보여주는 안내 문구를 보강한다.

## Flow 2. 익명 상태에서 친구 요청

1. 사용자가 방 안에서 상대를 인지한다.
2. 친구 요청 액션을 보낸다.
3. 상대는 요청을 받지만, 실제 프로필은 보지 못한다.
4. 요청 수락 전까지 두 사람은 계속 익명 상태다.

체크포인트:

- [x] 친구 요청 도메인이 있다.
- [x] 친구 수락 전 익명 유지 정책이 확정되었다.
- [ ] 친구 요청 버튼 노출 조건을 정한다.
- [ ] 친구 요청 화면에 보여줄 최소 정보 범위를 정한다.

## Flow 3. 친구 수락과 프로필 공개

1. 상대가 친구 요청을 수락한다.
2. 두 사용자는 친구 관계가 된다.
3. 친구 관계 화면과 친구 전용 경험에서 프로필을 공개한다.
4. 이후에는 친구 기반 1:1 대화로 이어질 수 있다.

체크포인트:

- [x] 친구 수락 도메인이 있다.
- [x] 친구 수락 후 프로필 공개 정책이 확정되었다.
- [ ] 수락 직후 어떤 화면으로 이동시킬지 정한다.
- [ ] 수락 직후 1:1 채팅을 자동 생성할지 정한다.

## Flow 4. 친구 이후의 관계 유지

1. 친구 목록에서 상대를 다시 찾는다.
2. 프로필이 공개된 상태로 1:1 채팅 또는 상호작용을 이어간다.
3. 필요하면 친구 해제 또는 이후의 안전 기능으로 관계를 정리한다.

체크포인트:

- [x] 친구 목록 도메인이 있다.
- [x] 개인 채팅 영역이 앱 구조에 있다.
- [ ] 친구 해제 후 공개 정보 회수 정책을 정한다.
- [ ] 차단/신고 흐름을 추가한다.
