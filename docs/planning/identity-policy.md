# Identity Policy

이 문서는 `익명 상태`와 `프로필 공개 상태`를 언제 전환하는지 정리합니다.

## 기본 원칙

- 익명 채팅은 실제 프로필과 바로 연결되지 않는다.
- 친구 요청만으로는 프로필이 공개되지 않는다.
- 친구 수락 후에만 프로필이 공개된다.
- 익명 채팅 로그는 친구가 된 뒤에도 익명 문맥을 유지한다.

## 상태별 공개 정책

| 상태 | 상대에게 보이는 정보 | 보이지 않아야 하는 정보 |
| --- | --- | --- |
| 익명 그룹채팅 참여 중 | 방 안 익명 식별자, 메시지, 방 안 활동 정보 | username, avatar, 상세 프로필 |
| 친구 요청 발신 후 대기 | 익명 식별자, 요청 상태 | 실제 프로필, 개인 상세 정보 |
| 친구 요청 수락 후 | 친구용 프로필, 친구 목록 상 정보 | 익명방 과거 로그와 프로필의 직접 연결 |
| 친구 해제 후 | 정책 미정 | 정책 미정 |

## 익명 식별 방식

익명 식별자는 `실제 프로필` 대신 방 문맥 안에서만 쓰는 정보여야 합니다.

가능한 방향:

- 방별 익명 번호
- 방별 별칭
- 방 문맥 안에서만 유효한 아바타 표현

현재 채팅 도메인에는 `anonymousIndex` 개념이 이미 존재하므로, 방 문맥 익명 식별자를 유지하는 방향이 자연스럽습니다.

## 친구 수락 전 정책

- [x] 친구 요청 수락 전까지는 익명으로 남긴다.
- [x] 요청을 받은 사람도 상대의 실제 프로필을 바로 볼 수 없게 한다.
- [ ] 친구 요청 화면에서 어떤 최소 정보까지 보여줄지 확정한다.
- [ ] 친구 요청 메시지 허용 여부를 확정한다.

## 친구 수락 후 정책

- [x] 친구 수락 후에는 프로필 공개 상태로 전환한다.
- [ ] 공개할 필드를 확정한다.
- [ ] 친구 수락 후 자동으로 1:1 채팅을 열지 확정한다.
- [ ] 친구 수락 후에도 익명 그룹채팅에서는 익명 상태를 유지할지 문구로 명시한다.

## 권장 공개 범위

초기에는 아래 정도만 공개하는 편이 안전합니다.

- display name
- username
- avatar
- 한 줄 소개 또는 상태 메시지

초기부터 너무 많은 프로필 정보를 공개하면 익명성의 장점이 약해집니다.
