# 핵심 게임 루프

## 기본 루프

1. 사용자가 플레이 모드를 선택한다.
2. 사용자가 플레이 기준 날짜를 선택한다.
3. 서버는 해당 날짜에 대응하는 `전 거래일 시장 replay 데이터`를 불러온다.
4. 가상 자산과 시작 조건을 지급받는다.
5. 재생되는 시세 흐름 안에서 코인을 거래한다.
5. 최종 손익과 수익률을 계산한다.
6. 결과를 저장하고 랭킹 또는 인증으로 연결한다.

## 플레이 구조

### 시작

- 시즌 또는 일반 모드 선택
- 플레이 기준 날짜 선택
  - 예: `2026-04-10`
- 선택한 날짜에 대응하는 전 거래일 replay day 로드
- 시작 자금 설정
  - 예: 100만원, 1,000만원
- 플레이 조건 설정
  - 단일 코인
  - 여러 코인
  - 제한 기간
  - 제한 거래 횟수

### 진행

- replay가 시간 순서대로 진행됨
- 차트 확인
- 코인 선택
- 매수 / 매도
- 현재 보유 자산 확인
- 누적 수익률 확인
- 현재 구간은 실제 시장이 아니라 `전날 저장 데이터의 순차 재생`임

### 종료

아래 조건 중 하나로 종료될 수 있다.

- 플레이 기간 종료
- 목표 날짜 도달
- 강제 종료 선택
- 특정 미션 완료

## replay 개념

- 사용자는 과거 전체 데이터를 한 번에 보는 것이 아니다.
- 앱은 선택한 날짜에 대응하는 전 거래일 시장 흐름을 작은 단위 이벤트로 순차 재생한다.
- 사용자는 그 재생 중인 현재 시점까지만 정보를 본다.
- 따라서 체감은 실시간 투자와 비슷하지만, 실제 데이터는 선택한 날짜 기준 전 거래일의 과거 데이터를 서버에 미리 적재한 것이다.

## 게임 모드 제안

### 1. 연습 모드

- 자유롭게 날짜를 골라 replay 투자
- 랭킹 반영 없음
- 학습/튜토리얼 용도

### 2. 챌린지 모드

- 고정된 replay 날짜와 조건
- 동일 조건으로 유저 간 성과 비교
- 랭킹 반영

### 3. 시즌 모드

- 일정 기간 운영
- 시즌 종료 시 최종 랭킹 집계
- 보상 / 배지 부여 가능

## 플레이 재미 포인트

- 같은 시장에서도 결과가 갈리는 선택의 차이
- 구간 선택과 타이밍에 따른 성과 차이
- 적은 자금으로 큰 수익률 만들기
- 하락장에서 살아남기
- 남의 플레이 결과와 비교하기

## 중요한 밸런스 포인트

- 초기에 너무 복잡한 거래 규칙을 넣지 않는다.
- 수수료는 MVP에서는 단순화한다.
- 레버리지는 초기에 제외하거나 매우 제한한다.
- 호가는 MVP에서 제외한다.
- 체결은 replay tick 기준 가격으로 단순화한다.
- 랭킹은 절대 수익보다 `수익률`, `위험 관리`, `조건 충족률`을 함께 고려할 수 있다.
