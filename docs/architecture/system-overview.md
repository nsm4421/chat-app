# 시스템 개요

## 상위 구조

앱은 크게 5개 축으로 나뉜다.

- 인증
- 프로필
- 시세 데이터
- 투자 플레이
- 커뮤니티 / 랭킹

## 권장 기능 경계

### feature_auth

- 로그인
- 회원가입
- 세션 유지
- 비밀번호 재설정

### feature_profile

- 프로필 설정
- 아이디 정책
- 아바타
- 향후 확장
  - 밴 상태
  - 유저 등급
  - 평판
  - 배지

### feature_market

- 코인 목록
- replay 가능한 날짜 조회
- replay tick 데이터 조회
- replay 차트 데이터 조회
- 코인 메타데이터

### feature_investment

- 플레이 세션 생성
- replay day 연결
- 가상 잔고 관리
- 주문 기록
- 보유 포지션
- 손익 계산
- 플레이 종료 처리

### feature_community

- 인증 글
- 댓글 / 반응
- 피드
- 신고

### feature_ranking

- 모드별 랭킹 집계
- 시즌 보드
- 통계성 지표

## 백엔드 방향

### 1. 시세 데이터

- 운영 서버가 플레이 기준 날짜에 대응하는 전 거래일 시장 데이터를 미리 수집/적재한다.
- 앱 런타임에는 거래소에서 실시간 시세를 직접 받지 않는다.
- 앱은 선택한 날짜에 대응하는 replay 데이터만 조회한다.

### 2. replay 데이터

- replay day 단위로 준비된 데이터셋이 있어야 한다.
- 재생용 tick 이벤트와 차트용 candle 데이터가 분리되어야 한다.
- MVP에서는 호가를 저장하지 않는다.

### 3. 게임 계산

- 초기에는 클라이언트 계산 + 서버 저장 가능
- 랭킹/인증 신뢰성이 중요해지면 서버 검증 로직 필요

### 4. 기록 저장

- 플레이 세션
- 주문 로그
- 최종 결과
- 시즌 결과

## 중요한 설계 원칙

- 플레이 기록은 재현 가능해야 한다.
- 플레이 기록은 특정 replay day와 특정 replay sequence를 기준으로 복원 가능해야 한다.
- 랭킹 대상 데이터는 서버 기준으로 검증 가능해야 한다.
- 커뮤니티 인증은 플레이 결과 원본과 연결돼야 한다.
- profile은 auth와 분리해 장기 확장에 대비한다.
